# Embodied Agent Atlas

**An evidence-linked Awesome collection, bilingual reading site, and portrait/landscape paper-card studio for embodied agents.**

[Website](https://hongboduan.github.io/awesome-embodied-agents/) · [Update runs](https://github.com/hongboduan/awesome-embodied-agents/actions) · [简体中文](README.zh-CN.md) · [Setup](docs/setup.md) · [Contribute](CONTRIBUTING.md) · [Data contract](docs/data-contract.md)

Explore how embodied agents perceive space, maintain memory, plan, call skills, monitor execution, and improve from feedback. VLA and world-model papers are included where they help explain the agent system.

## What is included

- A curated seed collection with original-source links and explicit review levels.
- Search and capability filters, paper details, method comparison, and a research map.
- Two card formats backed by the same record: 16:9 landscape and 3:4 portrait, with PNG export.
- A standard-library Python pipeline for paginated arXiv discovery, identifier deduplication, and revision tracking.
- GitHub Actions daily discovery at **08:17 Beijing time**, plus manual runs.
- Generated Awesome index, JSON, BibTeX, and RSS. The website runs without a backend or API key.

The workflow runs on source pushes, daily at 08:17 Asia/Shanghai, and on manual dispatch. The site reports actual discovery runs. Website publication additionally requires the one-time Pages setting described in [Setup](docs/setup.md); paper updates continue independently.

## Run locally

Python 3.10+; no pip packages required for the pipeline.

```bash
python -m unittest discover -s tests -v
python scripts/build.py
python -m http.server 8000 --directory dist
```

Open `http://localhost:8000`. Static assets use relative paths, including GitHub Pages project subpaths.

To perform a real arXiv update (requires outbound HTTPS):

```bash
python scripts/update.py
python scripts/build.py
```

Set your repository and public website URLs in `config.json`, then follow [GitHub setup](docs/setup.md). No model API key is needed or used. Automatic discovery preserves the English abstract; it does **not** invent a Chinese deep read or auto-promote candidates.

## Editorial and update policy

| Status | Meaning |
| --- | --- |
| `candidate` | Automatically discovered metadata; labels and claims await review. |
| `source-checked` | Original abstract or author project checked; not a full-paper review. |
| `full-review` | A paper-specific full reading with evidence and limitations. |

`data/seed-*.json` is editorial content. `data/candidates.json` contains automatic candidates. `data/versions.json` records current arXiv versions without overwriting an earlier editorial interpretation. `data/events.json` records discovery and revision events. Code availability is checked and labeled manually; automated code-release detection is not implemented in this first version.

Discovery uses a seven-day overlap, serial requests with at least a three-second gap, and pagination. All network pages must succeed before candidate and revision stores are written. On failure, old content and the last successful watermark remain intact; the failure status is still published and the workflow is marked failed. The pipeline updates and deploys in one workflow, so it does not depend on a bot commit triggering a second workflow.

Paper figures and quoted abstracts remain the property of their authors. Links are provided to original sources. Exported BibTeX is a convenience metadata export; check complete author names and final venue metadata before submission. Cross-paper benchmark numbers are not treated as a common leaderboard.

## Structure

```text
web/                 Static website and card templates
data/seed-*.json      Human-reviewed paper records
data/candidates.json Automatic discovery queue (created by updater)
data/versions.json   Observed source versions (created by updater)
data/events.json     Source change events (created by updater)
scripts/update.py    arXiv discovery and revision tracking
scripts/build.py     Site, Awesome, RSS, JSON and BibTeX builder
tests/               Offline behavioral checks
.github/workflows/   Daily discovery and Pages deployment
```
